# 绘制与验收

## 角色与动作图集

先锁角色外观参考与同一套笔触。每个角色至少记录脸、发型/体色、衣着、头身比和标志物。家人之间需要年龄差时，参考原书哥哥姐姐约 14–16 岁的青少年比例：头相对更小、躯干与四肢更长；弟弟妹妹保持儿童比例。年龄范围是原书设定，按新任务调整。

可用提示词骨架（替换花括号内容后提交）：

```text
Use the attached image as CHARACTER IDENTITY AND ART STYLE REFERENCE.
Create a transparent RGBA animation sprite atlas: exactly 3 columns × 3 rows,
nine equal cells in reading order, fixed camera, consistent figure scale.
Character: {identity, age proportions, clothing and colors}.
Action: {target action and ordered key poses}.
Warm watercolor/gouache and colored-pencil picture-book illustration.
Exactly one consistent character per cell; stable face and anatomy.
Keep the full body and every prop completely inside each cell, with 12–16%
clear padding on all sides. No text, numbers, borders, paper backdrop,
checkerboard, haze, scenery, extra limbs or duplicate props.
```

生成时为透明背景设置实际工具参数 `transparent_background: true`。修改已有图必须引用正确的已查看图片；角色参考和动作参考分别标明用途，避免滑梯、服装或背景被错误沿用。

**检查顺序：** 原图实际行列 → 透明 alpha → 逐格角色和完整道具 → 动作连续性 → 导出动画。工具返回的尺寸可能不同于提示词，读取实际尺寸后再按格等比例缩放、透明补边；不要直接把矩形人物拉伸成方形。角色或道具已被原图切掉时，应补画源图，增加画布不能补回缺失部分。

## 原书八动作的可观察标准

| 动作 | 关键姿态与接触关系 | 原图选帧参考 |
|---|---|---|
| 滑滑梯 | 顶部坐好 → 向下滑 → 滑到底部；保持同一滑梯 | 前 8 格 |
| 跑步 | 左右腿交替迈步、屈膝蹬地、手臂反向摆动 | 9 格，可连两周期 |
| 跳绳 | 绳在身后 → 头顶 → 身前 → 跳起从脚下通过 → 落地；双手持续握柄 | 9 格 |
| 游泳 | 身体近水平，手臂交替前伸划水，腿踢水，头在水面上 | 9 格，可连两周期 |
| 骑自行车 | 双手握车把、双脚随脚踏转动、两轮完整，头盔保持一致 | 9 格，可连两周期 |
| 跳远 | 预蹲 → 摆臂 → 双脚蹬地 → 腾空前移 → 双脚落地屈膝缓冲 | 9 格 |
| 爬树 | 手脚交替抱住树干向上，树与枝叶完整、接触位置可信 | 原书仅前 6 格 |
| 开汽车 | 手握方向盘、身体与手有动作、车轮辐条变化；车辆与安全带稳定 | 9 格，可连两周期 |

以上选帧只适用于对应的原书图集；新图按实际内容选，不机械删除最后一行。开汽车等情境按角色和教学内容明确是虚构/模拟，画面与句子含义一致。

`atlas_to_webp.py` 对全组姿态用一个包围框和固定变换，默认输出 620×620。它保留格内姿态变化，**不自动修正错误肢体、道具或接触关系，也不自动添加跳跃/前进轨迹**。需要位移时修改项目中的合成代码，并对全组位移后的边界重新验收；勿逐帧自动居中，否则会抹掉位移并产生抖动。原书起始停顿约 500 ms、末帧停顿约 1000 ms，可作为观察节奏起点。

## 场景与文字

场景单独生成或使用有权使用的素材，留出主体活动区、明确地面或水面，避免场景里再出现第二个同名主角。背景是实际插画，不仅改变底色。句中的位置词单独记录，例如：简洁→这里、公园→公园里、学校→学校里、家→家里、森林→森林里、海边→海边、医院→医院里、动物园→动物园里。

场景 `water: true` 表示背景已有自然水面，游泳页关闭辅助水池。普通背景需要水池时，将对应动作页设 `pool: true`。人物、道具和背景的比例与接触关系仍需实看。

## 本次交付验收

按改动范围做必要验证；完成一项后先同步该项正式成品、清理该项过程件，再开始下一项。

1. **素材实查：** 所有新增/修订图集逐格看；所有动画解码全部帧，核尺寸、帧数、一次播放标记、时长和透明边缘。每组至少看首中末帧并以正常速度看完整动作，检查手脚、绳柄、车轮、滑梯和树冠是否完整。程序帧差只能证明画面改变。
2. **互动实测：** 在交付 HTML 中点击所有角色 × 动作，核句子、替代文本和图片加载；每个场景至少切一次。实测翻页、返回封面、键盘、暂停/继续、重播以及末页→封面→首动作的自动循环。换角色/场景分别在自动与暂停状态检查，不能意外改变状态或提前翻页。
3. **单文件与离线：** 单文件逐项核内嵌资源与文件夹资源的字节对应；两种成品分别打开并重播。能测时用实际 `file://` 路径打开，另用本地 HTTP 排查差异。未完成双击/硬件测试要单列，不把 localhost 验证写成离线双击通过。
4. **布局与品牌：** 改过模板或长句时，覆盖桌面及 320、390、481、600、768 px 宽度的封面和最长句。看实际截图与元素边界：Logo 在左页文字上方；正文与页脚不重叠；左右页和按钮无横向溢出；右封面无重复 Logo。图片已加载还需检查显示年龄、脚底基线与场景位置。
5. **正式包回读：** `book.py verify` 解压式回读 ZIP，核 CRC、目录成员和逐文件字节；核单文件与文件夹清单、每项资源与源素材、最终哈希。生成脚本的通过不代替上述视觉与互动实测。
6. **交付与清理：** 留正式源图/配置/脚本、完整 HTML、文件夹/ZIP、使用说明、一份构建/验收记录和少量有效预览。删除本任务已不用的临时解压、试包、重复预览与失败候选；清理前核绝对路径和文件归属，清理后确认成品仍完整。审批拒绝时如实说明，不能绕过。

验收记录将“逐项实际检查”“抽样检查”“未检查”分开，附浏览器/设备与文件哈希。临床、课堂效果和真实手机表现需要相应实际证据。
